1요청과 결론

요청 — 앱 버전별로 AI 챗봇의 첨부 파일 UI 노출을 결정하고 싶다. 예를 들어 Android 앱 1.00.12 이상에서만 첨부 버튼이 보이게 하고 싶다.
SDK 설정으로 가능한가아니오 — 첨부 on/off 는 서버 설정이라 앱 버전을 구분하지 못합니다.
해결 방법입력 영역을 커스텀 컴포넌트로 교체하고, 첨부 버튼 노출을 직접 판단
판단 조건① 앱이 알려준 지원 여부 AND ② 기존 SDK 첨부 정책
적용 범위해당 플랫폼만 적용 가능 (예: Android 만). iOS·일반 웹은 기본 입력창 유지
앱 수정 필요 여부웹뷰 User-Agent 에 앱 버전이 이미 실려 있다면 앱 수정 불필요 (4.2)

버전 판단은 앱이 담당합니다. 웹은 앱이 넘겨준 값을 받아 쓰기만 하므로, 나중에 기준 버전이 바뀌어도 웹 코드는 수정할 필요가 없습니다.

2왜 설정만으로는 안 되는가

2.1 첨부 기능은 서버 설정

첨부 기능의 on/off 는 에이전트 단위 서버 설정(attachment_mode)으로 결정됩니다. SDK 는 이 값만 보고 첨부 버튼을 그릴지 말지 정합니다. 

// SDK 내부 — 첨부 버튼 컴포넌트
if (!isFileUploadEnabled) return null;   // attachment_mode 기준
attachment_mode첨부 버튼
off렌더 안 됨 — 완전히 사라짐
handed_off_only상담사 연결 후에만 노출
always항상 노출
이 값은 앱 전체에 일괄 적용됩니다 서버 설정이므로 앱 버전을 구분할 수단이 없습니다. 구버전 앱과 신버전 앱이 같은 에이전트를 바라보는 한, 둘은 같은 값을 받습니다.

2.2 입력 설정으로 꺼도 버튼은 남습니다

SDK 에는 첨부 메뉴 항목을 제어하는 클라이언트 설정이 있습니다.

config={{ conversation: { input: {
  gallery: { photoEnabled: false },   // 사진
  fileEnabled: false,                 // 파일
  camera: { photoEnabled: false },    // React Native 전용
}}}}

그런데 이것만으로는 + 버튼이 사라지지 않습니다. 위 2.1 의 조기 반환이 attachment_mode 기준으로만 걸려 있어, 메뉴 항목 배열만 비고 버튼은 계속 렌더됩니다.

실제로 확인한 결과 두 설정을 모두 false 로 두고 측정한 값입니다. 사용자는 + 를 눌렀는데 아무 항목도 없는 빈 시트를 보게 됩니다. 
첨부버튼_존재 : true     // 그대로 남음
파일input수   : 0
시트항목      : []       // 눌러도 빈 시트

따라서 입력 영역 자체를 교체하는 방법이 필요합니다.

3해결 구조

ConversationLayout.Footer 슬롯으로 입력 영역을 커스텀 컴포넌트로 바꾸고, 첨부 버튼 노출을 두 조건의 AND 로 판단합니다. 

첨부 버튼 노출 = 앱이 알려준 지원 여부  AND  기존 SDK 첨부 정책
                 (supportsAttachment)      (attachment_mode 등)
조건출처역할
supportsAttachment 네이티브 앱 → 웹뷰 앱 버전 판단 (예: 1.00.12 이상)
createAttachmentRules(...).isEnabled() SDK 서버 첨부 정책 반영
왜 두 조건을 모두 봐야 하나 앱 조건만 보고 열면, 나중에 서버에서 첨부를 꺼도(attachment_mode: off) 신버전 앱에는 버튼이 계속 남습니다. 반대로 서버 정책만 보면 버전 구분이 안 됩니다. 둘 다 만족할 때만 노출해야 합니다.
적용 범위를 좁히세요 입력창을 직접 구현하면 SDK 가 제공하던 동작(입력 비활성 상태, 다국어 문구, 스타일 등)을 직접 책임져야 합니다. 버전 분기가 필요한 플랫폼(예: Android)에만 적용하고, iOS 와 일반 웹은 기본 입력창을 그대로 두는 편이 안전합니다.

4구현

4.1 앱 → 웹으로 지원 여부 전달

버전 판단은 네이티브가 합니다. 앱이 자기 버전을 보고 첨부 UI 를 감당할 수 있는지 결정한 뒤, 그 결과만 웹뷰에 넘깁니다. 

// Android — 웹뷰 URL 에 파라미터로 전달하는 예
val supportsAttachment = BuildConfig.VERSION_NAME >= "1.00.12"   // 비교 방식은 앱 정책에 맞게

val url = Uri.parse(baseUrl).buildUpon()
    .appendQueryParameter("supportsAttachment", supportsAttachment.toString())
    .build().toString()

웹에서는 이 값을 읽습니다. 값이 없으면 구버전으로 간주해 끕니다.

// 미전달 시 false — 구버전 앱·예전 웹뷰 모두 안전하게 막힙니다
const supportsAttachment =
  new URLSearchParams(location.search).get('supportsAttachment') === 'true';
브릿지로 넘겨도 됩니다 URL 파라미터 대신 기존 웹뷰 브릿지로 전달해도 동일합니다. 다만 첫 렌더 전에 값이 정해져 있어야 버튼이 깜빡이지 않으므로, URL 파라미터가 더 단순합니다.

4.2 앱이 값을 넘기지 않아도 되는 경우 — User-Agent 활용

네이티브 앱이 이미 웹뷰 User-Agent 에 버전을 싣고 있다면, 앱을 수정할 필요가 없습니다. 웹에서 UA 를 읽어 직접 판단하면 됩니다. 

// 웹뷰 User-Agent 예시
Mozilla/5.0 (Linux; Android 14) ... Safari/537.36 appver='1.00.11' appos='a' appname='myapp'
필드의미예
appver앱 버전1.00.11
appos앱 OSa (Android)
appname앱 이름myapp

파싱과 버전 비교 구현입니다.

// 따옴표가 있어도(없어도) 동작하도록 느슨하게 읽습니다.
function readUAField(ua, key) {
  const matched = ua.match(new RegExp(`${key}\\s*=\\s*['"]?([^'";,\\s)]+)`, 'i'));
  return matched?.[1];
}

export function parseAppInfo(ua = navigator.userAgent) {
  return {
    name: readUAField(ua, 'appname'),
    os: readUAField(ua, 'appos'),
    version: readUAField(ua, 'appver'),
  };
}

// ⚠️ 문자열 비교를 쓰면 안 됩니다 — '1.00.9' > '1.00.12' 가 참이 됩니다.
export function isVersionAtLeast(version, minimum) {
  if (!version) return false;
  const toParts = (v) => v.split('.').map((p) => Number.parseInt(p, 10) || 0);
  const current = toParts(version), target = toParts(minimum);
  for (let i = 0; i < Math.max(current.length, target.length); i += 1) {
    const left = current[i] ?? 0, right = target[i] ?? 0;
    if (left !== right) return left > right;
  }
  return true;   // 완전히 같은 버전
}

적용 코드입니다. 앱이 명시적으로 넘긴 값이 있으면 그 값을 우선하고, 없으면 UA 로 판단합니다.

const MIN_ANDROID_VERSION_FOR_ATTACHMENT = '1.00.12';

const explicit = new URLSearchParams(location.search).get('supportsAttachment');
const appInfo = parseAppInfo();

const supportsAttachment =
  explicit !== null
    ? explicit === 'true'
    : appInfo.os === 'a' && isVersionAtLeast(appInfo.version, MIN_ANDROID_VERSION_FOR_ATTACHMENT);
일반 브라우저·iOS 는 자동으로 꺼집니다 UA 에 앱 정보가 없으면 version 이 undefined 라 isVersionAtLeast 가 false 를 돌려줍니다. appos === 'a' 조건까지 걸려 있어 iOS 앱도 영향을 받지 않습니다.

실제 파싱·판정 결과입니다. (기준 1.00.12)

UA 의 버전파싱 결과첨부 노출
1.00.11myapp / a / 1.00.11미노출
1.00.12 (경계)myapp / a / 1.00.12노출
1.01.0myapp / a / 1.01.0노출
1.00.9myapp / a / 1.00.9미노출 (문자열 비교였다면 노출됐을 값)
따옴표 없는 포맷myapp / a / 1.00.12노출
appos='i' (iOS)myapp / i / 9.9.9미노출
앱 정보 없음- / - / -미노출

어느 방식을 쓸 것인가

① UA 에서 읽기② 앱이 값 전달
앱 수정불필요 (이미 UA 에 있다면)필요
기준 변경 시웹 코드 수정앱에서 처리, 웹 수정 불필요
판단 주체웹앱
취약점UA 포맷이 바뀌면 깨짐전달 누락 시 꺼짐
UA 방식의 주의점 UA 포맷은 앱이 언제든 바꿀 수 있고, 바뀌면 조용히 깨집니다. (파싱 실패 → undefined → 첨부가 꺼진 채 아무 에러도 안 남음)

적용 전에 실제 기기의 UA 문자열을 반드시 확인하고, 앱 측에 UA 포맷을 바꿀 때 알려달라고 공유해 두세요. 위 코드처럼 명시적 전달값을 우선하게 해 두면, 나중에 앱이 값을 넘기도록 바뀌어도 웹 수정 없이 전환됩니다.

4.3 첨부 정책 읽기

SDK 의 첨부 정책은 아래 API 로 읽습니다. 서버 설정이 그대로 반영됩니다.

const { createAttachmentRules } = useMessengerSessionContext();
const { chatSDK } = useMessengerContext();

const rules = createAttachmentRules({
  channel,
  uploadSizeLimit: chatSDK.appInfo?.uploadSizeLimit,
});
속성의미
isEnabled()현재 첨부 가능 여부 (attachment_mode 반영)
supportedMimeTypes허용 형식 — accept 에 그대로 사용
maxAttachmentCount최대 첨부 개수
isSupportedMimeType(type)형식 검사
getUploadSizeLimit(type) / ...InMB(type)용량 제한

4.4 커스텀 입력창

핵심만 추린 구현입니다. 전체 코드는 샘플의 AppAwareMessageInput.tsx 를 참고하세요.

import {
  useConversationContext,
  useMessengerContext,
  useMessengerSessionContext,
} from '@sendbird/ai-agent-messenger-react';

export function AppAwareMessageInput({ supportsAttachment }) {
  const { channelSource, messageSource, state } = useConversationContext();
  const { chatSDK } = useMessengerContext();
  const { createAttachmentRules } = useMessengerSessionContext();

  const channel = channelSource.channel;
  const inputDisabled = state.input.disabled;   // AI 응답 중 등

  const rules = createAttachmentRules({
    channel,
    uploadSizeLimit: chatSDK.appInfo?.uploadSizeLimit,
  });

  // ★ 두 조건의 AND
  const showAttachment = supportsAttachment && !!channel && rules.isEnabled();

  const send = async () => {
    if (files.length > 0) {
      await messageSource.sendFileMessage({ file: files[0], message: text || undefined });
    } else {
      await messageSource.sendUserMessage({ message: text });
    }
  };

  return (
    <div>
      {showAttachment && (
        <>
          <button aria-label="파일 첨부" disabled={inputDisabled}
                  onClick={() => fileInputRef.current?.click()}>+</button>
          <input type="file" style={{ display: 'none' }} ref={fileInputRef}
                 accept={rules.supportedMimeTypes.join(',')}
                 multiple={rules.maxAttachmentCount > 1}
                 onChange={(e) => pickFiles(e.currentTarget.files)} />
        </>
      )}

      <textarea value={text} disabled={inputDisabled}
                onChange={(e) => setText(e.target.value)} />

      <button aria-label="메시지 보내기" disabled={inputDisabled} onClick={send}>전송</button>
    </div>
  );
}
반드시 지켜야 할 두 가지 ① state.input.disabled 를 따르세요. AI 가 응답 중이거나 추천 답변 선택을 기다리는 동안 SDK 는 입력을 막습니다. 이 값을 무시하면 사용자가 그 사이에 메시지를 보낼 수 있습니다.

② 첨부 전 용량·형식·개수를 검사하세요. rules 의 값으로 직접 검사해야 합니다. 서버에서 거부되면 사용자는 이유를 알 수 없습니다.

4.5 푸터 슬롯에 연결

<FixedMessenger ...>
  <FixedMessenger.ConversationChildren>
    <ConversationLayout.Footer
      component={() => <AppAwareMessageInput supportsAttachment={supportsAttachment} />}
    />
  </FixedMessenger.ConversationChildren>
</FixedMessenger>
기존 푸터 커스터마이징과 함께 쓸 때 ConversationLayout.Footer 슬롯은 하나만 적용됩니다. 종료된 대화의 "대화 시작" 버튼처럼 이미 푸터를 커스터마이징하고 있다면, 하나의 컴포넌트 안에서 함께 렌더해야 합니다. 
export function AppAwareFooter({ supportsAttachment }) {
  return (
    <>
      <StartNewConversationButton />
      <AppAwareMessageInput supportsAttachment={supportsAttachment} />
    </>
  );
}

5동작 확인 결과

샘플에 적용해 실제로 확인한 결과입니다. (첨부 정책: attachment_mode: always, 이미지만 허용, 1개)

조건첨부 버튼비고
supportsAttachment 미전달 (구버전 앱) 미노출 입력창·전송은 정상 동작
supportsAttachment=true (신버전 앱) 노출 accept, multiple 에 서버 정책 그대로 반영
확인 항목결과
허용 형식 반영accept="image/png,image/jpeg,image/jpg"
개수 제한 반영multiple=false (최대 1개 설정)
AI 응답 대기 중입력·첨부·전송 모두 비활성
텍스트 전송정상 — 에이전트 응답 확인
이미지 + 텍스트 전송정상 — 말풍선 표시 후 첨부 상태 해제
확인 완료 앱이 넘긴 값에 따라 첨부 버튼이 노출/미노출로 갈리고, 노출될 때는 서버 첨부 정책(형식·개수·용량)이 그대로 적용되는 것을 확인했습니다.

6구현 시 유의 사항

값이 없을 때는 끄세요

supportsAttachment 가 전달되지 않으면 구버전 앱으로 간주해 첨부를 막는 것이 안전합니다. 위 예시의 === 'true' 비교가 이 역할을 합니다.

버전 비교는 문자열 비교에 주의

"1.00.9" > "1.00.12" 는 문자열 비교에서 참이 됩니다. 자릿수가 다른 버전 체계를 쓴다면 숫자 단위로 쪼개 비교하세요. 이 판단은 앱에서 하므로 웹에는 영향이 없습니다.

SDK 기본 입력창의 기능을 직접 책임집니다

입력 영역을 교체하면 다국어 문구, 입력 비활성 처리, 스타일, 접근성 레이블을 직접 구현해야 합니다. 문구는 useLocalizationContext() 의 stringSet 을 쓰면 SDK 의 다국어 설정을 그대로 따를 수 있습니다.

적용 플랫폼을 분리하세요

버전 분기가 필요 없는 iOS·일반 웹까지 커스텀 입력창을 쓰면 관리 부담만 늘어납니다. 해당 플랫폼에서만 푸터를 교체하고, 나머지는 기본 입력창을 쓰는 구성을 권합니다.

서버 설정이 더 간단한 경우

앱 버전 구분이 필요 없고 첨부를 완전히 끄거나 켜기만 하면 된다면, attachment_mode 설정만으로 충분합니다. 이 가이드의 커스텀 구현은 버전별 분기가 필요할 때만 쓰세요.
